## Mom Test 워크북 — MagicSquare_1004

### 페르소나:
> **초등 3~4학년 담당 수학 교사, 공립학교, 경력 5년+, 주 1회 이상 ‘수와 연산’ 단원에서 패턴·덧셈 활동을 직접 준비하는 사람**

- Mom Test 기준: “모든 교사”가 아니라 **이미 비슷한 행동을 하는 구체적 한 사람**
- 좋은 페르소나 예: “방과 후 수학 지도를 하는 학부모”, “마방진을 시험 출제에 쓰는 중등 수학 교사” 등 **인터뷰한 실제 사람** 기준

---

### 인터뷰 답변 (과거 사실):
> **미래 의견·칭찬·가설 확인이 아니라, “지난번에 실제로 한 일”만 적기**

예시 (가상 — 실제 발언으로 교체 필요):
- “지난 학기 **매주 일요일 1~2시간** 마방진·숫자 퍼즐 워크시트를 **직접 만들었다**.”
- “아이들이 ‘대각선 합이 왜 같아야 해요?’라고 물었을 때, **칠판으로 15분 설명**했지만 **3명은 여전히 이해 못 했다**.”
- “네이버에 ‘마방진 문제’ 검색했는데 **중·고등 수준**이 많아서 **초등용으로 쓰기 어려웠다**.”
- “난이도 다른 문제를 주려고 **같은 유형을 3~4버전** 손으로 바꿔 썼다.”

❌ 쓰면 안 되는 답:
- “앱 있으면 좋을 것 같아요”
- “당신 아이디어 좋네요”
- “앞으로 쓸 의향 있어요”

---

### 표면 문제 (금지 — 솔루션 섞인 문장):
> **우리가 만드는 것(앱·자동 생성·AI)이 문장에 섞인 ‘가짜 문제’**

예시 (의도적으로 잘못 쓴 문장):
- “교사들은 **마방진 앱**이 필요해서 **퍼즐을 자동 생성**하고 싶어 한다.”
- “**MagicSquare_1004**로 **워크시트를 한 번에 출력**할 수 있으면 문제가 해결된다.”

→ 솔루션(앱, 자동화, 우리 제품명)이 들어가면 **표면 문제**입니다.

### 진짜 문제 (한 문장):
> **솔루션 없이, 그 사람의 삶·업무·감정만으로 한 문장**

예시 (가설 — 인터뷰로 검증 필요):
- **“초등 수학 교사는 마방진·숫자 패턴 활동을 위해 매주 상당한 준비 시간을 쓰면서도, 아이 수준에 맞는 설명 자료와 난이도별 문제를 안정적으로 확보하지 못한다.”**

다른 페르소나면 한 문장이 달라집니다:
- 학부모: “아이와 함께 논리 퍼즐을 하고 싶지만, 어디서 어떤 난이도로 시작해야 할지 매번 검색·선별에 시간을 쓴다.”

## 1. 마지막으로 틀렸을 때

**Q1.** ✅  
마지막으로 4×4 격자에 빈칸 2개를 채웠는데 **합 34가 안 맞았던** 게 언제였어? 그때 **어느 줄**(행·열·대각선)부터 이상하다고 느꼈어?

**Q2.** ❌

## 8계층 — 세션 3에서 만드는 것만

### Rule (규칙)

- 4×4 격자, 값은 `0`(빈칸) 또는 `1~16`
- **마법합 = 34** — 각 **행 4개**, **열 4개**, **대각선 2개**의 합이 34
- 완성 격자에서는 **1~16이 중복 없이** 한 번씩 (부분 격자에서는 `0` 제외하고 검사)
- **문제 인식점(실패 조건) 예:** 한 줄이라도 합 ≠ 34 → **틀림**

### Command (명령)

| 명령 | 설명 |
|------|------|
| `validate(grid)` | 4×4 격자가 행·열·대각선 합 34 조건을 만족하는지 **판정** |
| *(내부)* `sum_line(cells)` | 한 줄(행/열/대각)의 합 계산 — Command를 돕는 최소 연산 |

→ 학습자 관점: *“지금 넣은 숫자들, 34 맞아?”* → `validate` 호출

### (Skill) — 선택

- 4×4 격자 읽기 / `0`과 채워진 칸 구분
- 행·열·대각선 **인덱스**로 줄 추출
- “**34가 안 맞아서**” → **어느 줄**이 34가 아닌지 사람에게 보여주는 **해석** *(세션 3 후반 옵션)*

### Test Loop (테스트 루프)

```
RED  → test: "34가 안 맞는" 격자(증거 ③ 상황) → validate() → False 기대 → 실패
GREEN → validate() 최소 구현 → 테스트 통과
REFACTOR → 중복 합산 정리 (범위 넘으면 다음 세션)
```

**테스트 케이스 (Mom Test 연결)**

|--------|-----------|------|------|

| B | 올바르게 채운 4×4 완성 마방진 | `True` | 판정 기준선 |
| C | 빈칸 2개(0) 포함 **부분** 격자 | 채워진 줄만 검사 정책 정의 | ② “빈칸 2개 넣었다” |

### (Skill) — 선택

- 4×4 격자에서 `0`과 채워진 칸 구분
- 행·열·대각선 **인덱스**로 줄 추출
- `False`일 때 **어느 줄**이 34가 아닌지 표시 *(증거 ③ “34가 안 맞아서” 대응)*

```

GREEN   → validate() 최소 구현 → 통과

```
