## 1. 개요

STEP 1에서 확정한 **진짜 문제**(10선 합 34 판정·확인 비용)를 TDD로 구현하기 위해, ECB 아키텍처와 Dual-Track 테스트 전략을 반영한 **최소 Harness**와 **AI 협업 규칙**을 마련했다.

본 세션에서는 **골격만** 생성했으며, 도메인 로직·테스트 assert 본문은 포함하지 않는다.

---

## 2. 도메인 규칙 (`.cursorrules` SSOT)

| 항목 | 규칙 |
|------|------|
| 격자 | 4×4 |
| 값 | `0`(빈칸) 또는 `1~16` |
| 빈칸 | **정확히 2개** (`0`) |
| 마방합 | **34** (MagicConstant SSOT — 리터럴 산재 금지) |
| 검증 | 10선 — 행 4 + 열 4 + 대각선 2 |
| 출력 | `int[6]` → `[r1, c1, n1, r2, c2, n2]` — **1-index** 좌표 |

### 오류 코드 (boundary 전담)

| 코드 | 담당 |
|------|------|
| `E001`~`E007` | boundary — 정의·발생·변환 |
| `E001`~`E005` | **entity 처리 금지** |

entity는 도메인 불변식·판정만 담당하며, I/O·오류 코드·외부 계층에 의존하지 않는다.

---

## 3. 아키텍처 (ECB)

```
boundary  ──→  control  ──→  entity
  (I/O)      (유스케이스)    (도메인)
```

| 계층 | 역할 | import 규칙 |
|------|------|-------------|
| **entity** | 격자·마방합·빈칸 규칙 | **entity → \* import 금지** |
| **control** | 유스케이스 오케스트레이션 | entity만 호출 |
| **boundary** | 입력 파싱, 출력 직렬화, E001~E007 | control 호출 |

---

## 4. Dual-Track TDD

| Track | 대상 | Mock | 테스트 ID | 파일명 |
|-------|------|------|-----------|--------|
| **Logic** | entity, control | Domain Mock **금지** | `D-*` | `test_d_*.py` |
| **UI** | boundary | Mock **허용** | `U-*` | `test_u_*.py` |

### 디렉터리 매핑

| 소스 | 테스트 (Track) |
|------|----------------|
| `src/entity/` | `tests/entity/` (Logic) |
| `src/control/` | `tests/control/` (Logic) |
| `src/boundary/` | `tests/boundary/` (UI) |

### TDD 규칙

- 사이클: **RED → GREEN → REFACTOR**
- **assert 완화·`skip`·`xfail` 금지**
- 테스트 하나 = 행동 하나
- AI 작업 시 **Phase / Layer / Track** 선언 필수
