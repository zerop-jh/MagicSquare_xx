# MagicSquare_1004 STEP 1 — Mom Test 인터뷰 보고서

## 개요

MagicSquare_1004 프로젝트 STEP 1에서 Rob Fitzpatrick **Mom Test** 방식의 고객 발견 인터뷰를 진행했습니다.
페르소나는 **4×4 부분 마방진을 손으로/코드로 다루는 학습자**이며, 솔루션 제안 없이 과거 행동·불편·비용을 끌어내는 것을 목표로 했습니다.

## 프로젝트 배경 (과제 정의)

- **대상:** 4×4 마방진 (1~16, 마법합 34)
- **과제:** 빈 칸 2개의 위치를 찾고 올바른 숫자를 채워 완성
- **설계 맥락:** ECB(Entity-Control-Boundary) 분류, 문제 인식점 도출 (슬라이드 자료 기준)

## 인터뷰 진행 요약

| 단계 | 내용 |
|------|------|
| 페르소나 | 4×4 부분 마방진을 손으로/코드로 다루는 학습자 |
| 질문 1 | 마지막으로 부분 마방진을 다룬 시점·목적·상황 |
| 응답 | 프로젝트 소개 슬라이드 공유 (정의, ECB, 연습 목표) |
| 추궁 1 | 손/코드 여부, 처음부터 끝까지 소요 시간(분) |
| 보완 답변 | “지난번에 빈칸 2개 넣었다가 34가 안 맞아서 20분 헤맸다.” |
| 종료 | 표면/진짜 문제 도출, Mom Test 증거 3줄 확보 |

## Mom Test 평가

### 통과한 항목

- **과거 행동:** “지난번에 빈칸 2개 넣었다” — 실제로 한 일
- **구체성:** 소요 **20분**, 실패 원인 **합 34 불일치**
- **불편·비용:** “헤맸다” — 시행착오에 시간 소모

### 통과하지 못한 항목

- **손/코드 여부·정확한 날짜:** 아직 미확인
- **솔루션 혼입 (초기 응답):** 슬라이드의 `SquareValidator`, `MissingFinder`, `Solver`, ECB 분류는 설계·솔루션 언어

### 확보된 사실

- 4×4 부분 마방진, 빈 칸 2개, 마법합 34
- 페르소나: “4×4 부분 마방진을 손으로/코드로 다루는 학습자”
- **마지막 경험:** 빈 칸 2개를 채웠으나 합 34가 맞지 않아 **약 20분** 시행착오

## 문제 정의

### 1. 표면 문제 (잘못된 정의)

**“4×4 부분 마방진을 ECB 구조의 Solver·Validator 프로그램으로 만들면, 빈 칸 2개를 빠르게 채우고 합 34를 맞출 수 있다.”**

→ ‘만든다 / 프로그램 / Solver / ECB’가 문제 정의에 섞인 문장입니다.

### 2. 진짜 문제 (한 문장)

**4×4 부분 마방진에서 빈 칸 2개를 채운 뒤 행·열·대각선 합(34)이 맞는지 바로 판정하지 못해, 한 번의 시도만으로도 20분 가까이 시행착오를 반복한다.**

*(솔루션 이름 없음 — 불편·비용·판정 중심, 인터뷰 발화 기반)*

## Mom Test 증거

| # | 인용 | 적합 여부 |
|---|------|-----------|
| 1 | “4×4 부분 마방진을 손으로/코드로 다루는 학습자” | △ 페르소나 (역할) |
| 2 | “지난번에 빈칸 2개 넣었다가 … **20분 헤맸다**” | ✓ 과거 행동 + **비용** |

**결론:** Mom Test 증거 3줄 확보. 진짜 문제 문장은 위 인용을 근거로 작성함.

## 인터뷰 규칙 (적용 기준)

1. 한 번에 질문 1개
2. 금지: “만들면 좋겠어?”, “이 기능 필요해?”, “TDD 하면 어때?”
3. 허용: “마지막으로 ~했을 때”, “그때 몇 분 걸렸어?”, “뭐 때문에 포기했어?”
4. 모호한 답 → 추궁 1개만
5. 솔루션 언급 시 “그건 나중” — 불편으로 되돌리기

## 후속 조치 (선택)

3. 결국 **풀었는지**, **포기했는지**
